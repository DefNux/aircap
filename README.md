# AIRCAP — AI Incident Response Capability

A reproducible rig that **attacks an AI application, proves the attack was invisible, adds
detection, proves detection fires, auto-collects prompt-chain evidence, contains it, and
then re-runs the attack to prove the containment holds.**

Plenty of material describes AI incidents. This project produces the *evidence* — the
artifact an incident manager owns, not a blog post.

```
10/10 attacks reproduce        14/14 detections fire        0 expectation gaps
9 runbooks cover 14/14 detections     188 evidence rows collected in 0.33s
make ir-demo:  5 attacks succeed -> contain -> THE SAME 5 ATTACKS NOW FAIL
57 Terraform resources plan-clean      checkov 146 passed / 0 failed
4 attacks still defeat a fully hardened baseline  <- the finding, documented not hidden
```

> **Complete: all 6 phases.** Full measured results in [`docs/RESULTS.md`](docs/RESULTS.md).

## What is real and what is simulated

Stated first, because it matters more than the demo.

| Layer | Reality |
|---|---|
| Telemetry **schemas** | Faithful to Amazon Bedrock model invocation logs and CloudTrail `bedrock:InvokeModel` data events. Detections transfer to real AWS unchanged. |
| Telemetry **contents** | Generated by this lab. **Not** captured from a real AWS account — Bedrock has no free tier. |
| Model plane | Local. `stub` (deterministic, no GPU) or `ollama` (real 3B quantized inference). |
| Analytics | DuckDB, running the same SQL Athena would. |
| AWS infrastructure | Terraform, **`plan`- and policy-verified only. `apply` has never been run.** |
| Cloud log parsing | Synthetic samples in faithful VPC Flow / Route 53 / NSG formats. |

**Read [`engine/METRICS.md`](engine/METRICS.md) before quoting a timing number.**
Time-to-detectable, triage and containment durations are *measured*. MTTD is *modelled*
from a stated 60-second poll interval. **MTTR is not claimed** — human response time was
never measured.

## Quick start

```bash
make venv
make console        # -> http://127.0.0.1:8099   (recommended)
```

Or from the CLI:

```bash
make attack            # 10 attacks under their own postures
make detect            # 14 detections
make matrix            # attack x detection coverage matrix
make attack-hardened   # control test: every attack with all controls ON
make verify            # all of the above, in order
make ir-demo           # attack -> detect -> contain -> re-attack -> blocked
make discover          # shadow-AI scan of this endpoint
make atlas             # regenerate ATLAS coverage from the STIX bundle
```

## Operator console

`make console` → **http://127.0.0.1:8099**, nine views: Overview, Attacks, Detections,
Matrix, Response, Shadow AI, Query, Reference.

Run attacks individually or as the hardened control test; inspect the evidence rows behind
any detection; build the coverage matrix; execute runbooks in triage or respond mode; read
generated incident timelines and postmortems; scan for shadow AI; query telemetry with
ad-hoc SQL.

**Loopback only, and deliberately so.** It can run attacks, apply containment and wipe the
lab, so it is an administrative interface over an intentionally vulnerable application. It
has **no authentication** — do not expose it. The SQL console accepts only `SELECT`/`WITH`.

## The proof loop

```
STEP 1  5 attacks run                           -> 5/5 SUCCEEDED
STEP 2  detections                              -> 9/14 fired
STEP 3  runbooks execute, containment applied   -> 8 actions in effect
STEP 4  quarantine directory                    -> 5 documents removed from retrieval
STEP 5  THE SAME 5 ATTACKS RE-RUN               -> 5/5 blocked
STEP 6  incident artifacts                      -> timelines, postmortems, evidence packs
```

Step 5 is the point: containment that cannot be re-tested is a claim, not a control.
Containment is real state the running app honours — the retriever skips quarantined
documents, disabled tools and blocked hosts are refused — and it **overrides the
vulnerability toggles**, because an incident-response decision must not be undone by
whatever posture the app happens to be running in. `make ir-lift` reverses it.

## Residual risk — the most useful output

Five attacks succeed with **every control enabled**. Four have no preventive control at
all; the fifth is answered by the cloud layer.

| Attack | Not prevented because | Coverage |
|---|---|---|
| A02 RAG corpus poisoning | provenance markers stop the model *obeying* retrieved instructions, not *answering from* attacker facts | detect-only (D011) |
| A03 Tool-definition poisoning | tool descriptions render into the trusted system prompt; nothing inspects the catalogue | detect-only (D005, region-aware) |
| A04 Confused deputy | one application identity, no per-user authorization between agent and tools | detect-only (D013) |
| A08 Token-flood DoS | per-prompt size ceiling exists; per-principal rate budget does not | detect-only (D012) |
| A10 Unauthorized principal | prevention is IAM, absent from the lab by design | **closed in AWS** by `bedrock:GuardrailIdentifier` + SCP |

The control test asserts against each attack manifest's stated expectation rather than
"nothing may succeed" — a zero-successes assertion would only create pressure to weaken the
expectation until it went green. And three of those four have **no AWS-native answer
either**; see [`mappings/AWS_CONTROLS.md`](mappings/AWS_CONTROLS.md).

## Architecture

```

lab/        vulnerable RAG+agent app  ─┬─> bedrock-logs/  prompts + completions
            telemetry emitters         ├─> cloudtrail/    who called, no bodies
                                       └─> agent-traces/  tool calls, retrieval
query/      6 DuckDB views (Athena-compatible SQL)
detections/ 14 SQL · 14 Sigma · 23 Wazuh rules
runbooks/   9 executable runbooks ──> incidents/<id>/ evidence + timeline + postmortem
engine/     IR engine, containment, metrics
iac/aws/    57 Terraform resources: telemetry plane + preventive controls
mappings/   detection ↔ AWS · detection ↔ Azure · ATLAS coverage (STIX-generated)
console/    FastAPI + single-page operator UI, 23 endpoints
```

## Vulnerability toggles

Every weakness is an explicit, logged opt-in. All `false` is the hardened baseline, which
is how before/after numbers stay honest.

| Toggle | Disables | Enables |
|---|---|---|
| `AIRCAP_TRUST_RETRIEVED_CONTENT` | retrieval provenance markers | indirect injection, RAG poisoning |
| `AIRCAP_NO_TOOL_ALLOWLIST` | tool allowlist, path sandbox, id validation | traversal, secret exfiltration |
| `AIRCAP_ALLOW_UNSCOPED_FETCH` | egress allowlist, private-range denial | model-driven SSRF incl. IMDS |
| `AIRCAP_NO_OUTPUT_FILTER` | response redaction | data leakage to the user |
| `AIRCAP_DROP_GUARDRAIL` | guardrail attachment | guardrail-absent invocation |

Defence is layered on purpose: a planted directive the model obeys still hits the tool
sandbox. Full exfiltration requires *two* toggles.

## Shadow-AI discovery

```bash
make discover            # four lenses, no root required
make discover-capture    # adds live TLS/QUIC SNI capture (needs sudo)
make discover-cloud      # classify AI egress in synthetic VPC/Route53/NSG samples
```

Local inference runtimes (with GPU attribution), unauthenticated model APIs on a port, AI
browser extensions by stable id, and egress to 43 provider hostnames. Risk scoring inverts
for local runtimes: prompts stay on-device, but the runtime is unmanaged and invisible to
network-only DLP.

## Frameworks

**NIST SP 800-61r3** (CSF 2.0 Community Profile), **MITRE ATLAS v5.4** and **OWASP GenAI
Top 10 (2026)**. The ATLAS matrix is generated from the official STIX 2.1 bundle and fails
on an invalid technique id — which is what makes it evidence rather than decoration.

## Scope and ethics

Clean-room: no employer data, incidents, configuration or detection logic. All attack
traffic and telemetry is self-generated. Every attack targets this lab, bound to
`127.0.0.1`, on the author's own machine. Credentials under `lab/` are fixed fake strings
that exist so exfiltration detection has something to match.
