# AIRCAP — AI Incident Response Capability

A reproducible rig that **attacks an AI application, proves the attack was invisible, adds detection,
proves detection fires, auto-collects prompt-chain evidence, contains it, and reports MTTD/MTTR.**

Plenty of material exists describing AI incidents. This project is about *producing the evidence* —
the artifact an incident manager owns, not a blog post.

> **Status: Week 1 of 6 complete.** Target app, AWS-faithful telemetry and the analytics layer are
> working. Attack pack, detection library, IR engine, shadow-AI discovery and cloud portability follow.

## What is real and what is simulated

Stated plainly, because this distinction matters more than the demo:

| Layer | Reality |
|---|---|
| Telemetry **schemas** | Faithful to Amazon Bedrock model invocation logs and CloudTrail `bedrock:InvokeModel` data events. Detections written here transfer to real AWS unchanged. |
| Telemetry **contents** | Locally generated by this lab. **Not** captured from a real AWS account — Bedrock has no free tier. |
| Model plane | Local. `stub` backend (deterministic, no GPU) or `ollama` (real 3B quantized inference). |
| Analytics | DuckDB, which runs the same SQL Athena would. |
| AWS infrastructure | Terraform, `plan`/`validate`-verified only — **not** `apply`-verified. |

## Architecture

```
discover/   shadow-AI on endpoints  ─┐
lab/        vulnerable RAG+agent app │→ bedrock-logs/  (prompt + completion)
            telemetry emitter        │→ cloudtrail/    (who called, no body)
                                     │→ agent-traces/  (tool calls, retrieval)
query/      DuckDB views  ───────────┤
detections/ Sigma · SQL · Wazuh  ────┤
runbooks/   executable IR  ──────────┴→ incidents/<id>/ evidence + timeline + MTTD/MTTR
iac/        Terraform for real AWS
mappings/   detection ↔ AWS · detection ↔ Azure
```

## Quick start

```bash
make venv          # venv + deps
make smoke         # generate telemetry across all three streams (no GPU required)
make views         # list analytics views
make query SQL="SELECT ts, prompt_chars, completion FROM bedrock_invocations ORDER BY ts"
```

For real inference instead of the stub:

```bash
make ollama-pull && make ollama-serve      # 3B q4_K_M fits the 4GB VRAM budget
AIRCAP_MODEL_BACKEND=ollama make serve
```

## Vulnerability toggles

Every weakness is an explicit, logged opt-in. All `false` is the hardened baseline, which is how
before/after detection numbers stay honest.

| Toggle | Disables | Enables attack |
|---|---|---|
| `AIRCAP_TRUST_RETRIEVED_CONTENT` | retrieval provenance markers | indirect prompt injection, RAG poisoning |
| `AIRCAP_NO_TOOL_ALLOWLIST` | tool allowlist, path sandbox, id validation | path traversal, secret exfiltration |
| `AIRCAP_ALLOW_UNSCOPED_FETCH` | egress allowlist, private-range denial | model-driven SSRF (incl. IMDS) |
| `AIRCAP_NO_OUTPUT_FILTER` | response redaction | data leakage to the user |
| `AIRCAP_DROP_GUARDRAIL` | guardrail attachment | guardrail-absent invocation |

Defense is layered on purpose: a planted directive that the model obeys still hits the tool sandbox.
Full exfiltration requires *two* toggles, which is the point.

## Analytics views

`bedrock_invocations` · `cloudtrail_bedrock` · `agent_traces` · `tool_calls` · `retrievals`

`cloudtrail_bedrock` deliberately carries no prompt or completion. That asymmetry — the control plane
proves *that* a model was called, only invocation logging proves *what was said* — is the first thing
an AI incident responder has to internalise.

## Frameworks

Detections and runbooks are mapped to **NIST SP 800-61r3** (CSF 2.0 Community Profile),
**MITRE ATLAS v5.4** and the **OWASP GenAI Top 10 (2026)**. The coverage matrix is generated from the
ATLAS STIX 2.1 bundle rather than hand-maintained.

## Scope and ethics

Clean-room: no employer data, incidents, configuration or detection logic. All attack traffic and
telemetry is self-generated. Every attack targets this lab, bound to `127.0.0.1`, on the author's own
machine. Credentials under `lab/` are fake strings that exist so exfiltration detection has something
to match.
